# Effect: COMPLETENESS (missing metadata)

Guides the resolution of `RelationNotFound` (RNF), `AttributeNotFound` (ANF),
and other metadata-related errors by loading database context.

## Common categories

-   `RelationNotFound` (RNF)
-   `AttributeNotFound` (ANF)
-   `TypeError`
-   `SymbolError`

**Official Documentation**: For information on how to extract metadata from your
source system, see [Generate metadata for translation][generate_metadata].

## RelationNotFound (RNF) / AttributeNotFound (ANF)

These errors occur when the compiler cannot find the schema definitions or type
information for tables, views, columns, or types referenced in the query. While
RNF and ANF are the most common indicators of missing metadata, `TypeError` or
`SymbolError` can also arise from incomplete type definitions in the metadata
package.

### Resolution workflow

RNF and ANF mean the translation is not clean. Don't stop at reporting them: the
best fix is the real object definitions (step 1). Without them, use DDL
suggestions (step 2).

#### 1. Verify metadata configuration

-   If a metadata zip package (generated by the BigQuery Migration Service
    (BQMS) metadata extractor) is provided:
    -   Ensure it is uploaded to a Cloud Storage bucket.
    -   Pass its Cloud Storage path to `metadataFilePath` in `translate_query`
        (Interactive) or `metadataFilePaths` in `translate_batch_queries`
        (Batch).
-   If metadata is configured but RNF persists:
    -   **Check Schema Search Path / Database Redirection**: Verify if the
        compiler is looking in the correct schema. If the source queries use
        three-part names (db.schema.table) that need to be mapped to BigQuery
        project.dataset.table, you must configure database/schema redirection.
        Use `experimental_object_rewriter` in the
        [BigQuery Migration Service (BQMS) YAML configuration](translation_yaml_config.md)
        to redirect entire databases or schemas to their target BigQuery
        counterparts.
    -   **Inspect Metadata**: If you have tools to unzip or view the file, check
        if the missing table actually exists in the metadata package. If not,
        ask the user to verify the extraction inputs.

#### 2. Generate DDL suggestion (primary method for missing DDLs)

Always prioritize using the BigQuery Migration Service (BQMS) DDL generation
tools to automatically infer and suggest schema DDLs for missing relations
(`RelationNotFound`) over manually authoring DDL statements.

-   **Interactive Workflow**:

    1.  Call `generate_ddl_suggestion` specifying the input query and
        project/location details.
    2.  Poll `fetch_ddl_suggestion` with the returned ID until successful,
        retrieving SQL from `suggestion.suggestion_content`.
    3.  Prepend the generated DDL statements to the query and re-translate.

-   **Batch Workflow**:

    1.  Call `generate_batch_ddl_suggestion` specifying `sourceBaseUri` (Cloud
        Storage input folder) and `targetBaseUri` (Cloud Storage output folder).
    2.  Poll `fetch_batch_ddl_suggestion` using the returned suggestion ID until
        completed.
    3.  Download the generated DDL file (e.g., `generated_metadata.sql`) from
        the Cloud Storage output path returned in
        `suggestion.cloud_storage_uri`.
    4.  Inspect the generated DDL statements to ensure static database names and
        valid schema references are present.
    5.  Copy/upload the generated DDL file(s) into the Cloud Storage input
        directory alongside input queries and re-run `translate_batch_queries`.
        Note that DDL SQL files generated for missing metadata should be plain
        `.sql` files, not zipped. The `.zip` format is strictly reserved for
        metadata zip files generated by the official BigQuery Migration Service
        (BQMS) metadata extractor dumper tool.

#### 3. Review the re-translated output

Suggestions are in the source dialect and inferred from usage, and may not cover
every object.

-   Compare error counts with the previous iteration, fix or report what
    remains, and recommend providing a metadata zip for exact results.
-   **Interactive**: The re-translated output contains the BigQuery version of
    the suggested DDL: show it in your response for the user to review. The
    prepended DDL only helps BigQuery Migration Service (BQMS) resolve objects,
    so keep it out of the translated query you deliver.
-   The re-translated query can also change because of the guessed schema (e.g.
    `*` expanded into the inferred columns, or casts for guessed types). Compare
    it with the first translation; where they differ only because of the guessed
    schema, keep the first translation's form and tell the user why.

#### 4. Manual mock DDL (fallback only)

Only manually construct mock `CREATE TABLE` statements if DDL generation tools
are unavailable or fail to produce valid table definitions.
