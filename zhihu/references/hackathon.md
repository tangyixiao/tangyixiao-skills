## 参赛流程

### 1. 完成报名

在活动页面进入报名流程，填写个人、联系方式和学校等信息，并按页面要求完成身份验证。

报名成功后，按页面提示添加活动小助手并加入官方交流社群，以获取赛程通知、赛事答疑和组队信息。

### 2. 创建或加入队伍

登录活动页面，进入“我的项目”：

- 单人参赛可以直接创建自己的队伍；
- 团队参赛由队长创建队伍并邀请队员；
- 被邀请的队员需要先完成报名；
- 队员通过知乎昵称搜索和邀请；
- 按页面要求填写队伍名称、成员、合影和参赛想法链接等信息。

队伍信息发生变化时，应在活动允许的时间内及时更新。

### 3. 开发作品

确定作品目标和使用的知乎能力后，完成可在线访问的产品 Demo。

黑客松项目可按需求接入知乎开放平台的搜索、热榜、直答、问题发现与回答摘要，以及授权用户的创作列表、关注和收藏。应用开发按对应 Reference 选择 HTTP 接口；需要通过 CLI 调用时，再检查 CLI `capabilities` 和 `--help`。本人全文、评论和统计遵循 [创作能力](creator.md) 的本人身份限制，不扩展为 OAuth 代查。

黑客松另外提供知乎故事和知乎知识内容接口。需要使用时读取 [黑客松故事与知识内容 API](hackathon-content-api.md)。

调用有额度限制的开放能力时，应在应用层进行缓存和请求去重。禁止批量、高频、无意义发布，或使用接口进行刷屏、恶意灌水和垃圾内容推送。

### 4. 创建黑客松项目

作品提交入口开放后，由队长在活动页面进入队伍详情，点击“创建项目”。

按页面要求填写：

- 项目名称；
- 参赛主题或赛道；
- 项目介绍；
- 可运行的线上 Demo 地址；
- 产品说明或计划书；
- 项目 icon 和封面图；
- GitHub/Gitee 仓库地址（选填）；
- 演示视频地址（选填）；
- 知乎登录回调地址（使用 OAuth 时填写）。

项目保存后仍可在活动允许的范围内继续修改；最终应在截止时间前完成发布。

## 知乎账号 OAuth

作品需要知乎账号登录、获取授权用户基础信息，或读取其创作列表与摘要、关注和收藏时，按 [黑客松 OAuth 接入](hackathon-oauth.md) 配置。是否接入由作品需求决定；凭证领取时机也见该文档。

## 提交作品

在上方赛程表列明的作品提交窗口内，由队长进入活动页面完成提交；实际截止时间以活动页面当前展示为准。

### 必交材料

- 可公开访问并能实际操作的线上 Demo；
- 产品说明或计划书。

产品说明是初审的重要材料，应说明：

- 项目的核心创作思路和目标用户；
- 用户如何完成核心体验；
- 整体技术方案；
- 使用了哪些知乎开放能力；
- 项目与知乎社区生态的契合点；
- 项目对社区用户的实际价值。

### 选交加分材料

- GitHub 或 Gitee 代码仓库；
- 在线演示视频。

### 提交前检查

1. Demo 可以从公网正常打开并完成核心流程。
2. 项目名称、介绍、赛道、封面和产品说明已经完成。
3. 代码仓库和视频链接可以被评委访问。
4. 使用 OAuth 时，回调地址与活动页面登记值完全一致。
5. App Key、Access Secret、OAuth Token 等凭证没有出现在代码仓库、前端响应、日志、截图或视频中。
6. 接口失败、额度耗尽和空数据都有真实的错误或降级提示。
7. 页面显示、接口调用和登录流程经过实际运行验证，未把“代码已完成”写成“线上已可用”。
