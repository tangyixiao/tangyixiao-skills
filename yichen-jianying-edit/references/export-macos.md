# 本机原生 MP4 导出

仅在用户明确要求成片/导出时执行。默认草稿交付不运行本入口。

## 输入、边界与命令

入口使用本机剪映 11.4.2 的原生 `ExportService` 和 MP4 writer，不调用外部 FFmpeg 合成、烧字幕或重新封装。FFmpeg 只用于完整解码检查、抽帧与音频质检。

输入必须是 `build` 或 `edit build` 产生且可通过逐文件验证的独立快照，不是正在编辑的 live 草稿。之后在剪映中手工修改的内容不会自动进入旧快照；用户要导出最新手改内容时，不能悄悄改为导出旧 build。

```bash
python3 SKILL/scripts/headless_draft.py export --build ABSOLUTE_BUILD --out ABSOLUTE_WORK/NEW_EXPORT_JOB
```

大写路径是待替换参数。`--out` 必须是本次 `work/` 下不存在的新目录；成片固定为其中的 `render.mp4`。默认采用快照画幅与帧率、H.264/AAC、4 Mbps；可设置 `--bitrate`（100000–200000000 bit/s）与 `--timeout`（秒，默认 600）。不覆盖既有输出。当前版本只支持偶数画幅，16–7680；帧率 1–120 的参数范围不等于所有组合均已逐一验收。

导出前复核版本、build、原生库 hash、完整应用签名及开发者 Team ID；变化则停止。每次编译只使用本地标准 C++ 与已安装的原生引擎，需 Xcode Command Line Tools；编译临时文件和模块缓存显式放入本次 job 的 `compiler-tmp/`。本机专用组件不随 Skill 分发。

引擎在新的隔离进程中运行：禁止网络与账号数据读取，只能读取本次复制的用户素材，不能写入任务目录以外。不会附加正在运行的剪映进程，也不操作界面或修改 live 草稿；无需退出剪映即可导出已冻结的 build。

## 当前能力

- 已通过实际原生渲染与画面检查：本地视频、分段、混合速度、旋转画中画、中文标题/字幕、BGM/短音效；线性画面关键帧；已采集的叠化转场。PNG/GIF 的编辑器验收与导出验收分别记录，不据前者泛化后者。
- 叠化原声已与编辑器导出同一测试样本对照：两个同相 440 Hz 原声在 0.4 秒叠化区间，界面导出约 +6.019 dB、无界面约 +6.030 dB，仅差约 0.011 dB，与两路直接相加一致。它不是无界面链路独有问题，但无削波不代表响度合适；含叠化时仍返回 `native-dissolve-audio-overlap`，须检查真实音频，不能静默改音量或将这次测试泛化为所有音频都正确。
- 支持的素材/轨道与转换前快照保持一致。未知非空素材类别、片段/文字动画、曲线变速、未采集转场等会拒绝。
- 六种已采集的静态几何蒙版已通过隔离导出：历史 12 秒/360 帧样本显示圆形、矩形、线性、镜面、星形、爱心，以及圆角、羽化、反转、旋转和位移。与原生 UI 样片的彩色轮廓重合率为 98.37%–99.64%，不代表逐像素或源图颜色完全相同。导出从已签名安装包加载 `lumi_js_resources_video`，不修改账号、许可、功能开关或应用文件。蒙版 ID、参数类别和逐文件资源身份均检查；自定义/文字蒙版仍拒绝。
- 已采集的高清黑白、轻微抖动和橙色花字有新建草稿的原生播放、冷重开、UI 导出和同机 6 秒/180 帧隔离导出检查。花字仅重定位文字 JSON 字符串内的资源路径，未修改授权字段、原生运行配置或沙箱。正式入口仅接受这三个固定资源的身份、参数、轨道/花字样式绑定与逐文件字节；未知效果仍拒绝。技术支持不证明持续有效的会员权益、商用或再分发许可，使用前仍须有本次资源使用权限。
- 已采集的本地复合片段可导出冻结的 `edit build`：递归保留内部轨道、检查素材和子草稿文件，在原生异步恢复完成事件到达后才启动导出。4 秒/120 帧样本的嵌套字幕、画中画修改和 BGM 增益对照通过；只等待固定时间会过早导出成仅有音轨的文件，现已修复。此能力不代表复合草稿能在编辑器保存后保持结构；其首页登记仍被拦截，见 [edit-existing-macos.md](edit-existing-macos.md)。
- 多时间线、云端身份、未本地化的在线资源/模板，以及未采集的花字/滤镜/特效不在导出保证范围。不会读取钥匙串、付费下载或绕过原生授权限制。资源的原始会员/不可商用观察与 `entitlement_verified:false` 保留在警告里，不能把技术渲染通过改写成账号或许可证校验通过。

## 验收与证据

成功状态 `encoded-and-decoded` 只表示收到了原生完成事件、标准 MP4/H.264/AAC 检查通过、完整解码通过、素材和来源 build 没有变化。仍须查看实际输出，检查内容、字幕位置、变速、转场与结尾，并在涉及音量变化时检查音频；不能将解码成功等同于全部画面正确。

结果保存在 `result.json`，另有 `ffprobe.json`、`runtime-timeline.json`、输入 hash 清单、原生日志和完整解码日志。返回实际帧数、`expected_frames`、`frame_delta` 与 `duration_delta_seconds`：目前允许原生量化误差最多一帧，容器时长容差为一帧或 50 ms 中较大者；这些差异会显示，不能把存在差异的文件宣称为帧精确输出。

历史本机样本覆盖 25 / 30 fps、关键帧、叠化、静态蒙版和复合冻结快照；曾有实际少一帧的导出，结果如实报告差异。UI 输出还可能是文件名为 `.mp4` 的 QuickTime 容器，不能仅看扩展名判定为本入口的标准 MP4。不同版本、分辨率、帧率或效果组合仍需对应检查。

三个视觉资源的历史低分辨率独立检查为 **8/9**，不是全通过：640×360 花字彩色掩膜与 2K UI 缩小参考的 IoU 为 0.79685，未达到 >0.90，阈值未降低。文字、样式和位置经看图通过，但不能据此声称严格像素一致。叠化及 BGM 的合成信号客观测量也不等于任意声音的主观听感验收。

历史工作目录、真实草稿、图像和原生日志不随源码分发。发行整理后的实测结果见核心项目 `docs/VERIFICATION.md`；源码包装检查不替代以上历史原生验收，也不自动完成下一次用户素材的验收。

失败保留日志和部分文件，标为失败，不将部分 MP4 交付。没有自动重试、降级编码、移除效果或 UI 代操作。临时材料按本次删除授权处理；未授权则保留。
